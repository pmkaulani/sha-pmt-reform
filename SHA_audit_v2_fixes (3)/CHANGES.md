## Multi-property support (added after this audit, on request)
The original data model could not represent owning more than one of anything:
- `d.assets.includes('CAR')` was boolean and `vehicleType` was one value for the whole household — two cars priced as one, and a household with a beater + a luxury SUV could report "Standard Old" and make the luxury vehicle vanish from the AGI entirely.
- The one fraud check that tried to catch undisclosed vehicles (Flag 16, NTSA cross-check) had `declaredCount` hardcoded to `d.assets.includes('CAR') ? 1 : 0` — it could never represent more than one vehicle, so it either couldn't fire correctly or fired on anyone with 3+ NTSA-registered vehicles regardless of what they'd actually have declared.
- `landAcreage` was one number tied to one reported county — land split across an ASAL and non-ASAL county got one flat multiplier applied to the whole total.
- There was no field anywhere for owning a second house. `subletIncome` only captured income if reported; a paid-off vacant second property was completely invisible.

**What changed** (all in `AlgorithmSimulation.js` and `App.jsx`, fully backward compatible — every existing preset produces identical output; verified with `verify_logic.js`, a dedicated multi-asset test script, and an 800-household synthetic-population stress test with zero crashes):
- New optional array fields: `d.vehicles` (`{type}[]`), `d.landParcels` (`{acres, county}[]`), `d.rentalProperties` (`{monthlyRentCharged, isOccupied}[]`). Omit them and the code falls back to the legacy singular fields exactly as before.
- Each vehicle is now valued individually — `deriveVehicleList()` is shared between `calculateProposedModel` (valuation) and `calculateFraudRisk` (the now-fixed NTSA cross-check), so the two can't disagree about how many vehicles were declared.
- Each land parcel is valued using its *own* county's ASAL multiplier, not one multiplier applied to the household's total acreage.
- **Landlords are treated as a business, not a wealth signal**: rent from occupied units is counted as income (so it isn't double-counted as a separate asset value on top of the cash flow it already generates); vacant units get a conservative imputed monthly value (admin-configurable via `adminParams.vacantRentalImputedMonthly`, default KSh 8,000) since a paid-off empty rental house is real wealth that would otherwise stay invisible.
- New fraud flag, **Landlord Without Tax Registration**: 3+ rental properties, >KSh 50,000/mo in actual rental income, no KRA PIN. Unlike Flags 6/18 (fixed earlier for relying on demographic pattern-matching with no statistical basis), this one is grounded in an actual legal requirement — Kenya's Monthly Rental Income tax regime — so it's a specific, checkable compliance gap rather than a proxy for anything.
- New preset, **"Landlord (Multi-Property)"**: a Nakuru household with 4 rental units (3 tenanted, 1 vacant), one car, and one land parcel, demonstrating all of the above and correctly triggering the new fraud flag.
- UI: progressive disclosure in the form — everyone sees exactly the same single-vehicle/single-parcel experience as before by default; "+ Add another vehicle", "own land in more than one county?", and "own rental properties?" reveal the richer repeatable-list inputs only when needed.
- `generateSyntheticHousehold()` now occasionally generates multi-vehicle, split-parcel, and landlord cases, so the Bias & Compliance tab's fuzz testing actually exercises these paths instead of only the legacy single-item ones.

**Known simplification, flagged not fixed**: livestock stayed a single aggregate count (not itemized by species or split by parcel-county) — wasn't part of what was asked, and restructuring it wasn't free.

## Round 2: public transport fleets, Uber/Bolt, and land valuation accuracy (on request)

**Bug found in my own Round 1 fix**: Flag 17 ("Commercial Exemption Abuse") still only checked the single legacy `d.vehicleType` field against one `contextData.ntsaVehicleCategory` — it was never updated when `d.vehicles` was added, so a fleet owner with one falsely-declared COMMERCIAL vehicle mixed among several genuine ones would never get caught. Fixed to check every declared vehicle against a parallel `contextData.ntsaVehicleCategories` array (verified: correctly isolates "vehicle 3/3" in a 3-vehicle test fleet where only that one was mismatched).

**Matatu/boda/taxi fleet owners had an income gap identical to the one fixed for landlords.** The existing "Commercial Tool Exemption" only ever discounted the vehicle's *asset* value — nothing captured the actual income such a vehicle generates when a *hired* driver operates it under Kenya's common "daily target" arrangement (driver pays owner a fixed daily amount, keeps the rest). A single owner-operator's earnings already flow through `grossMpesaMonthly`; a fleet owner's cut from hired drivers usually doesn't. Fixed the same way as rental income: each vehicle can now declare `isOwnerOperated` (default true — assume already captured, add nothing) and, when explicitly false, `dailyTargetIncome`. Verified: a 3-matatu fleet with hired drivers at ~KSh 1,800–2,000/day each correctly adds ~KSh 150,800/mo in income on top of the vehicles' own (already-fixed) asset values; an owner-operator declaring the same vehicle type correctly adds zero fleet income, confirming no double-counting.

**Uber/Bolt drivers**: a solo driver's own earnings should already be reasonably captured via `grossMpesaMonthly` (Uber/Bolt payouts are M-Pesa-based in Kenya) plus the (now-correct) vehicle asset value — no separate fix needed there. A fleet owner running several cars on Uber/Bolt through hired drivers is covered by the same fix above. One **open policy question, deliberately left undecided in code**: gig drivers commonly use a PRIVATE-registered personal vehicle for ride-hailing without completing the formal NTSA PSV conversion. As written, Flag 17 would treat that identically to someone falsely claiming a matatu exemption on a vehicle never used commercially — but those aren't really the same thing. Documented in-code as a real choice for you to make: (a) leave as-is, gig drivers lose the exemption without PSV registration, or (b) add a separate `isGigEconomyDriver` declaration verifiable against Uber/Bolt account data instead of NTSA PSV status.

**Land valuation: sourced, but not what "according to stats where located" actually requires.** The KSh 80,000/acre base is real and cited in ASSUMPTIONS.docx ("Ministry of Lands average smallholding valuations") — not fabricated. But it's a single national average with only a 3-tier arid/semi-arid/other adjustment on top. Checked against real 2026 market data: non-ASAL rural farmland (Laikipia, Nakuru, Trans Nzoia, Narok) runs KSh 400,000–2,000,000/acre — 5–25x the model's base rate — and land in Nairobi's satellite growth corridors (Kiambu, Ngong, Ruiru, Kitengela, appreciating 13–15%/year) runs KSh 30,000,000+/acre — roughly 375x the base rate. A flat national figure is exactly the kind of location-blind proxy the project's own "Error by Design" framing criticizes the old system for using on housing materials — just applied here to land instead. Didn't invent per-county multipliers to patch this (that would just be a new unsourced number replacing an old one) — instead added an optional per-parcel `marketValuePerAcre` override plus an `adminParams.landValuePerAcre` default override, so real data (HassConsult's public quarterly Land Price Index, or county valuation rolls under the Unimproved Site Value system, both real and citable) can replace the flat default parcel-by-parcel as it's gathered. Verified: the same 1-acre Kiambu parcel prices at KSh 33,440 under the default rate vs KSh 18,972,640 under a realistic peri-urban override — roughly 570x apart, which is the actual scale of the problem this override exists to eventually close.

**Still missing, not addressed**: no asset class exists anywhere for general business value — a shop, kiosk, salon, or workshop's inventory/equipment has no representation beyond whatever revenue happens to flow through `grossMpesaMonthly`. Same invisible-wealth shape as the land and rental-property gaps, just for a third asset category. Flagging, not building, since it wasn't asked for this round.
